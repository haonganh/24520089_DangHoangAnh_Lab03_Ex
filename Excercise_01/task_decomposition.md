## 1. Assignment scope and source-of-truth decisions

Build a reusable `DeveloperCard` that presents a developer's avatar, name, role, metrics, and skills. Match the instructor's reference before adding enhancements.

### Required code contract

- Use a **pure function component** with **ES6 destructuring defaults**. The reference uses the named export `export function DeveloperCard(...)`.
- Component props and reference defaults:

  | Prop | Reference default | Requirement |
  | --- | --- | --- |
  | `fullName` | `'Tran Vinh Khiem'` | Visible developer name and meaningful image alternative text. |
  | `role` | `'Senior Systems Architect • UIT S3T'` | Visible role text. |
  | `avatarUrl` | `https://images.unsplash.com/photo-1534528741775-53994a69eda?w=240` | Source of the 64 × 64 avatar. |
  | `metrics` | `{ commits: 512, vdomNodes: 0, a11yScore: 100 }` | Render key/value pairs via `<dl>`. |
  | `skills` | `[{ id: 'sk-1', name: 'React 19 Fiber', tier: 'Core' }]` | Render a semantic list using stable IDs. |

- Render **one `<article>`** as the card's outer element, labelled by its `<h2>` through `aria-labelledby`.
- Use `<header>`, `<img>`, `<h2>`, and `<p>` in the card heading, with sensible heading hierarchy in the host page. The slide shows `<hgroup>`; keep it only if the project/browser support and instructor requirements allow it.
- Render metrics with `Object.entries(metrics).map(...)` inside `<dl>`; each `<dt>` and `<dd>` pair belongs to a **keyed `<Fragment key={k}>`**.
- Render skills inside `<ul className={styles.skills} aria-label="Engineered Skills">`, with one `<li>` per skill and a stable `key={s.id}` at the mapped element.
- Use `DeveloperCard.module.css` and `styles.card`, `styles.header`, `styles.metrics`, and `styles.skills`. Do not import legacy Ant Design global CSS merely to style this component.
- **No `<div>` elements anywhere in the `DeveloperCard` subtree**. A React Fragment adds no DOM wrapper.

### Instructor-slide inconsistencies and resolution

1. The narrative asks for reusable `<SkillBadge />` composition, but the displayed JSX maps directly to `<li>`. **First implement the displayed JSX; then refactor to a `SkillBadge` component that returns `<li>` without changing the resulting semantics.** Place the list `key` on the mapped `<SkillBadge key={s.id} ... />` after extraction.
2. The narrative says skill `level`, while the displayed JSX and default data use **`tier`**. Keep `tier` as the reference data contract. Do not silently rename it.
3. The narrative uses `aria-label="Skills"`, while the displayed JSX uses **`aria-label="Engineered Skills"`**. Use the displayed JSX label consistently.
4. The sample uses `id="dev-heading"` on `<h2>` with `aria-labelledby="dev-heading"` on `<article>`. This is sufficient for **one** card. If rendering multiple cards on the same page, switch to unique IDs (e.g., React `useId`) while preserving the labelled relationship.
5. The default `a11yScore: 100` is **example data, not evidence of a WCAG audit**.
